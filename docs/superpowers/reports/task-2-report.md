## What I implemented

- `src/i18n/uz.json`, `src/i18n/ru.json`: 76 keys each (75 from spec 4.2/4.3 + `hero.numeral` = `{hook}`).
  Generated by a script that parses the two code blocks in the spec and applies only
  `105 -> {hook}` and `99 000 -> {price}` (`{phone}` in `cta.or` and `{date}` in `state.teaser.note`
  were already templates in the spec). A re-check script rendered the templates back and compared
  every value to the spec text: zero mismatches. Glyph census: uz has 55x U+02BB, 8x U+02BC, 0 ASCII
  apostrophes, 0 NBSP; `«»`, `—`, `·` preserved. `103` in `footer.note` correctly left literal.
- `src/i18n.ts`: `Lang`, `isLang`, `getLang`, `t`, `applyI18n`, `setLang` exactly per the brief.
  - `getLang`: `?lang=` (uz/ru only) -> `localStorage.lang` (try/catch) -> `uz`.
  - `t`: fills `{hook}/{phone}/{price}/{date}` from `./config` (read at call time so `vi.mock` works);
    missing in requested lang -> `console.warn('[i18n] missing', key, lang)` then uz fallback; missing in
    both -> returns the key.
  - `applyI18n`: `textContent` for `[data-i18n]`; `<title>` sets textContent and `document.title`;
    `<meta>` sets the `content` attribute; `[data-i18n-attr="a:k,b:k2"]` sets each attribute (malformed
    pairs skipped); sets `<html lang>`; updates `link[hreflang="uz|ru"]` hrefs to this page with
    `?lang=<code>` (no hash) and is a no-op when there are none.
  - `setLang`: persists (try/catch), `applyI18n(document, lang)`, dispatches `langchange` with `detail: lang`.
- `src/state.ts`: `applyMode(root)` and `applyPhoneHint(root)` per the brief and the extra rules in the task
  context (span copies class list, adds `cta--disabled`, keeps `data-cta` value, `aria-disabled="true"`, no
  href; `.nodate` note only for teaser; live sets `a[data-cta]` href to `PHONE_TEL`; hint shown only when
  `PHONE !== HOOK`).
- `src/main.ts`: CSS imports, then `applyI18n(document, getLang()); applyMode(document);
  applyPhoneHint(document);`, then a click handler for `[data-lang]` that calls `setLang` and re-runs
  `applyMode` and `applyPhoneHint`.
- `vite.config.ts`: environment `jsdom`, plus `setupFiles: ['tests/setup.ts']`. `jsdom` added as dev dep
  (`^29.1.1`). `resolveJsonModule` was already enabled in `tsconfig.json`.

## Decisions worth a reviewer's eye

1. **Active-language state in `i18n.ts`.** `t(key)` with no `lang` uses the language last applied by
   `applyI18n`/`setLang` (falling back to `getLang()` before the first apply). Reason: with `getLang()`
   as the default, a visitor on `/?lang=uz` who clicks RU would get RU text from `applyI18n` but `t()`
   (used by `applyMode`) would still read the query and answer uz. Covered by a test.
2. **State copy is tagged with `data-i18n`.** `applyMode`/`applyPhoneHint` set `data-i18n` to the state key
   (`state.<mode>.cta`, `state.<mode>.note[.nodate]`, `cta.or`) on the elements they write. The replacement
   `<span>` deliberately does NOT inherit the original's `data-i18n`/`data-i18n-attr`/`href` (otherwise any
   later `applyI18n` pass would put the live "call 105" label back on a disabled button). Side effect: the
   explicit `applyMode`/`applyPhoneHint` re-run in `main.ts` after `setLang` (required by the brief and kept)
   is now redundant for correctness; a mutation test showed removing it does not fail any test. Harmless,
   left as specified.
3. **Delegated click handler** on `document` (`closest('[data-lang]')`) instead of binding to buttons at boot,
   so header buttons rendered by a later task or after boot still work. The `data-lang` value is validated
   with `isLang` before `setLang`.
4. **hreflang:** only `uz`/`ru` alternates are rewritten (spec: "hreflang uz/ru via ?lang"). An `x-default`
   link, if Task 8 adds one, is left untouched.

## Concern: Node 25 breaks `localStorage` under vitest + jsdom

This machine runs Node v25.9.0. Node 25 defines its own experimental global `localStorage`; without a valid
`--localstorage-file` it is a bare stub (no `getItem`/`setItem`/`clear`) that shadows jsdom's Storage, and
merely reading it prints `Warning: --localstorage-file was provided without a valid path`. First test run
after implementing `i18n.ts`: 14 of 14 i18n tests failed with `TypeError: localStorage.clear is not a function`.
Fix: `tests/setup.ts` always redefines `globalThis.localStorage` to `globalThis.jsdom.window.localStorage`
(never reading Node's getter, so no warning). Works on any Node version. Alternative considered:
`--no-experimental-webstorage` via execArgv; rejected because that flag does not exist on Node 20 and
`package.json` engines allows `>=20`. Production code is unaffected (browsers).
